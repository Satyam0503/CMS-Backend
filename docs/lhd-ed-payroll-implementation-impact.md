# LHD + ED Monthly Payroll — Implementation Impact

## Current relevant implementation

- ASP.NET Core 10 API, service, DTO, Mongo repository, utility, migration-runner, and xUnit test projects.
- MongoDB documents and a generic `IMongoDbRepository<T>`; company filtering is automatic only for entities implementing the audit interface through `BaseClass`.
- Monthly payroll is generated by `AutoPayrollServices.GeneratePayrollForMonthAsync` and stored in `EmpPayRoll`.
- Joining-date proration exists, but uses a string joining date and calendar-day divisor.
- No employee exit/termination date exists.
- Attendance is daily and status-code based; LHD and ED are supported.
- Configurable attendance statuses already provide paid/unpaid fractions.
- Leave approval and attendance are separate; no monthly attendance lock exists.
- RBAC uses module + Create/View/Edit/Delete permission constants via `ModulePermissionAttribute`.
- React uses MUI, Axios wrappers, module permissions, toast notifications, and route-level guards.

## Reusable files and functions

- `AutoPayrollServices` for monthly iteration, salary lookup, attendance lookup, proration, and payroll upsert.
- `PayRollServices.AddUpdatePayRoll` for payroll persistence.
- `BaseClass` for company/audit/soft-delete fields.
- `IMongoDbRepository<T>` for company-scoped CRUD.
- Attendance Settings page/API for company attendance configuration.
- Existing Payroll Settings and Payroll pages.
- `Result<T>`, `ModulePermissionAttribute`, and current middleware error/authorization conventions.

## Gaps 
 
- No effective-dated/versioned LHD+ED policy.
- No idempotent monthly attendance/payroll exception.
- No HR review decisions or mandatory review reason.
- No monthly attendance summary, validation, approval, or lock.
- Payroll does not block unresolved exceptions or unlocked attendance.
- No explicit payroll deduction lines or immutable calculation snapshot.
- No exit-date proration.
- No configurable divisor policy.
- No Mongo transaction/session abstraction in the generic repository.
- No dedicated fine-grained penalty permissions; existing Attendance/PayrollSettings permissions must be reused initially.

## Files requiring modification

- Employee, attendance, and payroll entities.
- Auto payroll and payroll services.
- Service registration and controllers.
- Attendance Settings and Payroll UI/API services.
- Tests and migration runner.

## New files genuinely required

- Penalty policy, monthly exception, and attendance summary entities/DTOs.
- One orchestration service and controller for policy, recalculation, review, validation, and lock.
- One safe Mongo migration for indexes/default policy.
- Focused tests.

## Database impact

MongoDB is schema-flexible. New collections are additive. Existing payroll documents gain optional deduction/snapshot fields. Employee exit date is optional. New unique indexes are required for policy version, monthly exception, attendance summary, and payroll month keys.

## Backward compatibility risks

- Legacy payroll has no snapshot and must remain readable.
- Existing attendance months have no locked summary; production enforcement needs a controlled rollout/backfill path.
- Existing employees may lack valid joining dates.
- New exit-date and snapshot fields must stay optional.
- Existing API response shapes will only receive additive fields.
- Current uncommitted Attendance Settings work must be preserved.

## Implemented production flow

1. Admin configures an effective-dated combined LHD+ED monthly limit (default 2).
2. Recalculation counts only attendance inside each employee's joining/exit eligible period and creates one idempotent monthly exception when the limit is exceeded.
3. HR/Admin reviews each pending exception with a mandatory reason and chooses waive, warning, half-day LOP, full-day LOP, or a custom fraction through the API.
4. Attendance validation calculates monthly summaries, checks missing weekday attendance and required checkout times, and refuses to lock while exceptions remain pending.
5. Payroll refuses to run for any eligible employee whose monthly attendance is not approved and locked, or whose exception remains pending.
6. Payroll clips salary proration to joining/exit dates, applies only a reviewed penalty decision, replaces the existing monthly payroll on rerun, and stores explicit deduction lines plus a calculation snapshot.

## Operational rollout

- Run the Mongo migration project before enabling the feature. It creates unique keys for monthly exception, monthly summary, and policy version records.
- For a payroll month, use **Recalculate & Load** under Attendance Settings, resolve all pending rows, then use **Validate & Lock Attendance** in Payroll Settings before **Process Salary**.
- Legacy payroll records remain readable because all new document fields are optional/defaulted.
- Existing closed months require a controlled attendance-summary backfill or one-time validation before payroll can be rerun.
